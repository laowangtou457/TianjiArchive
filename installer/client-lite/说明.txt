天玑档案管理系统 · 客户端（lite 版）使用说明
==================================================

版本：client-lite 1.0.0（对应服务端 1.0.0；2026-11-10 构建）
自检判据与 offline/smoke.sh 同一口径；判据若随服务端演进，本包必须随版本重建。

一、这是什么
  一个免安装的配置器：不改系统设置、不装软件、不联网、不需要管理员权限。
  解压后共 4 个文件，作用分别是：

    config.json            服务器地址等配置（双击 bat 会自动改写这个文件）
    配置天玑客户端.bat      双击运行：填服务器 IP -> 写配置 -> 建快捷方式 -> 自检
    自检.ps1               连通性自检脚本（也可单独双击复查，界面全在它里面）
    说明.txt               本文件

二、第一次使用（三步）
  1. 把整个 tianji-client-lite 文件夹解压到任意位置，例如 D:\天玑档案\ 。
     注意：不要把 bat 单独拖出来，四个文件必须放在同一目录。

  2. 双击「配置天玑客户端.bat」
     - 输入服务器 IP（例如 192.168.20.51），直接按回车则使用默认值；
     - 看到 [OK] config.json 已写入 即成功；
     - 桌面上会出现「天玑档案管理系统」快捷方式；
     - 紧接着自动跑三项连通性自检。

  3. 双击桌面快捷方式，浏览器打开系统登录页。

三、自检不通过怎么办
  自检三项，判据与服务器端 offline/smoke.sh 完全同一口径：

    1/3 网站服务   http://IP:8080/healthz        要求 HTTP 200 且正文为 ok
    2/3 后端接口   http://IP:8080/api/health     要求 status=ok 且 objectStorage.ok=true
    3/3 对象存储   IP:8333 的 TCP 直连           要求能建立连接

  三项全 PASS 才会显示 IS_PASS: YES。

  常见现象与定位（重要，先看这一条）：

  * 只有 3/3 红，1/3 与 2/3 绿
    -> 登录、检索都正常，但一上传就失败。这是「8333 端口没放通」，
       不是后端 bug。请让运维在服务器防火墙上放通 TCP 8333，
       并确认 tianji-seaweedfs 容器状态为 healthy。

  * 1/3 红
    -> 服务器网站服务没起来，或 IP 写错。请确认服务器上
       docker compose ps 里 tianji-web 为 healthy。

  * 2/3 红且 status=degraded
    -> 看自检输出里逐行列出的依赖，标 FAIL 的那一项没就绪。
       若是 objectStorage 标 FAIL，上传一定会失败，先查 tianji-seaweedfs 与 8333。

  * 三项全红
    -> 十有八九是 IP 写错，或本机与服务器不在同一内网。

  * 三项全绿但仍打不开系统
    -> 请把自检窗口内容整段复制给运维。

四、换服务器地址 / 换端口 / 只做复查
  * 换地址：重新双击「配置天玑客户端.bat」，填新 IP 即可（配置会被覆盖）。
  * 换端口：如果运维把 8080 或 8333 改成了别的端口（服务端 .env 里的
    WEB_EXPOSED_PORT / SEAWEEDFS_S3_EXPOSED_PORT），用记事本编辑
    config.json 里的 webPort / s3Port 保存，再单独跑一次「自检.ps1」。
  * 只做复查：直接双击「自检.ps1」，它不会改任何配置。
  * 端口以 config.json 为准；重跑 bat 会保留 config.json 里已有的端口。

五、受限电脑上的替代做法（不允许运行 bat 时）
  1. 用记事本打开 config.json，把 "serverAddr" 改成服务器 IP，保存；
  2. 浏览器直接访问 http://<服务器IP>:8080 ；
  3. 自检可手工执行：
     powershell -ExecutionPolicy Bypass -File .\自检.ps1

六、技术细节（给运维看）
  * 为什么 bat 里看不到中文：cmd.exe 解析含中文的 .bat 时会算错行偏移，
    中文行会被当成命令执行（报 "'xxx' 不是内部或外部命令"），加不加 UTF-8 BOM
    都一样，已在本项目构建机（Windows 11）上反复复现。因此
    「配置天玑客户端.bat」保持纯 ASCII，只负责 chcp 65001 与调用 PowerShell；
    全部中文界面放在 自检.ps1（UTF-8 with BOM），PowerShell 按 BOM 正确解析，
    任何控制台代码页下输出都不乱码。
  * 自检.ps1 为 UTF-8 with BOM + CRLF；config.json 为 UTF-8 无 BOM + CRLF。
  * 退出码（可被批处理或其他脚本直接调用）：
      配置器 0 成功 / 1 写配置失败 / 2 自检未通过
      自检.ps1 0 全部通过 / 2 存在问题
  * 快捷方式是标准 .url 文件，指向 http://<IP>:8080 ，用系统默认浏览器打开。
  * 全程无联网下载行为；不写系统目录、不写注册表、不安装服务、
    不需要管理员权限；卸载就是删掉这个文件夹和桌面快捷方式。
  * 若解压后提示「PowerShell 脚本 not found」，说明解压不完整，
    请重新解压并把 4 个文件放在同一目录。
  * 若解压后文件名出现乱码，请改用 7-Zip / WinRAR 解压（Windows 自带
    解压工具对部分 zip 的中文文件名处理不一致）。
