## 二、本轮交付了什么（先看这个，再决定测哪块）

### P3-A 鉴定与销毁

```
新建鉴定任务（按年度/保管期限/是否到期圈定已归档件）
   └─▶ 生成明细（每件一行，结论默认"未鉴定"）
        └─▶ 逐件或批量给结论：继续保管 / 延期保管 / 移交 / 销毁
             ├─▶ 点"执行"：继续保管只留痕；延期改保管期限；移交打移交标记
             └─▶ 销毁：必须先过审批 → R1 初审 → R4 批准 → 自动软删除进回收站
```

- 任务号自动生成 `JD2026-001`（数据库序列，不会重号）
- 明细只圈**已归档**的件，永久件不参与「到期鉴定」
- **销毁不进回收站前的状态**：结论先落 `appraisal_entry`，点「执行」才动档案表；未审批的销毁件执行时会被跳过并提示「待审批 N 件」
- 只有「所有明细都给了结论 **且** 都执行完」任务才变「已完成」——避免出现「三千多件没鉴定却显示完成」的假完成

### P3-B 开放审核

```
新建开放批次（按年度/密级圈定件）
   └─▶ 生成待审明细（超出审核人密级范围的件不进批次）
        └─▶ 四态审核：条目开放 / 原文开放 / 不开放 / 再审查
             └─▶ 提交审批（未审的件自动收口为"不开放"，理由"提交时未审核"）
                  └─▶ R1 审批通过 → 自动把 open_scope 写到档案表（幂等）
                       └─▶ 再审查队列：标记"再审查"的件单独排队，另行处理
```

- `open_scope` 三档：`NONE` 控制使用 / `ENTRY` 仅条目开放 / `FULLTEXT` 条目+原文开放
- 同步维护旧的 `open_flag`（OPEN / CONTROLLED），老查询不受影响
- 提交时**不阻塞**：哪怕几千件没审完也能提交（未审按最保守结论收口），这是刻意设计

### P3-C 可配置审批流引擎

| 能力 | 说明 |
|---|---|
| 四表模型 | `workflow_def` / `workflow_node` / `workflow_instance` / `workflow_task` |
| 流程定义 | 编码 + 业务类型 + 版本 + 启用开关；节点按 `seq` 顺序执行 |
| 节点要素 | 名称、处理角色（R1/R4/不限）、权限域（APPRAISAL/BORROW_APPROVE）、通过回调、是否允许驳回 |
| 待办池 | 按「岗位」而非「人」派单：谁有该角色谁就能在「审批中心 → 我的待办」看到 |
| 动作 | 同意（推进到下一节点或整单通过）/ 驳回（终止，必填意见）/ 撤回（发起人） |
| 回调 | 最后一节点通过后触发业务动作（`OPEN_BATCH_APPLY`、`APPRAISAL_DESTROY_EXEC`），**事务外执行 + 幂等** |
| 超时 | `scanTimeouts` 扫描超时环节；默认只告警不改状态（避免流程被自动推进） |
| 内置流程 | `WF-OPEN-BATCH`（R1 审核 → 应用标识）、`WF-APPRAISAL-DESTROY`（R1 初审 → R4 批准 → 执行销毁） |

### P3-D 前端

- 新增四个菜单：**档案鉴定**、**开放管理**（这两项在「档案业务」组）、**审批中心**、**档案知识库**（「检索利用」组）
- 菜单按权限域裁剪：`deptclerk1`、`reader1` 看不到鉴定/开放
- 借阅列表新增「利用单」按钮 → 新窗口 A4 打印（可存档的纸质凭证）

### P4-A 向量底座 + P4-B RAG / LLM Wiki

| 项 | 实现 |
|---|---|
| 向量库 | PostgreSQL 16 + **pgvector 0.8.1**（自建镜像，Alpine 源码编译，`with_llvm=no`） |
| 嵌入模型 | Ollama `nomic-embed-text`（768 维），8 条/批（>20 条会 abort） |
| 生成模型 | Ollama `qwen3:8b`，超时 180s（32b 单轮 30s+，不适合演示环境） |
| 切片 | 目标 400 字 / 上限 600 字 / 重叠 80 字；优先级 `document_text → kb_entry → full_text` |
| 检索 | **混合召回**：向量 0.65 + 2-gram 词法 0.35，词法强相关（整串命中/长查询高覆盖）时保底 0.9；候选按「每件最多 2 条」去重；权限过滤写在 SQL 里（不是先召回后过滤） |
| 问答 | 检索 Top-N 片段 → 拼提示词 → LLM 生成 → 回答带 `[1][2]` 引用，可点回原档 |
| 降级 | 嵌入不可用 → 纯词法召回 + 抽取式摘要；LLM 不可用 → 只返回片段与引用 |
| Wiki | 条目互链（人工/自动）、主题聚合、单件摘要 |

> 详细设计见 `docs/工作流与审批流设计.md` 与 `docs/RAG与知识库设计.md`。

### 数据核对 SQL

```sql
-- 开放标识分布（用例 B4）
SELECT open_scope, count(*) FROM archive_item WHERE deleted = false GROUP BY 1;

-- 某批次明细（看未审收口）
SELECT decision, count(*), count(applied_at) AS applied
FROM open_review WHERE batch_id = '<批次ID>' GROUP BY 1;

-- 销毁审批实例与节点进度
SELECT i.status, t.status AS task_status, n.seq, n.name, n.role_code
FROM workflow_instance i
JOIN workflow_task t ON t.instance_id = i.id
JOIN workflow_node n ON n.id = t.node_id
WHERE i.biz_id = '<任务ID>' ORDER BY n.seq;

-- 向量切片覆盖
SELECT count(*) AS chunks, count(DISTINCT item_id) AS items FROM item_chunk;
```
