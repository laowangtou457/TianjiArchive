## 二、本轮交付了什么（先看这个，再决定测哪块）

### P1 归档状态机（对齐泰坦 DARMS 收集链路）

```
未处理 ──预归档──▶ 预归档 ──确认归档──▶ 已归档
  │  ├──提交审核──▶ 待审核 ──通过──▶ 已归档（R1）
  │  │                  └──不通过（必填原因）──▶ 未处理
  │  └──无需归档──▶ 无需归档 ──撤回──▶ 未处理
  └──────── 确认归档可跨态直达（R1）────────┘
```

- 每次流转都写 `item_stage_log`（**只增不改**），件详情页底部可查时间线
- 确认归档时自动落 `archived_by / archived_at`
- 非法流转服务端拒绝（不靠前端藏按钮）

### P2 检索增强

| 项 | 改造前 | 改造后 |
|---|---|---|
| **索引覆盖** | ES 里只有 6 个文档，3469 件搜不到 | 3469 件全量入索引（重建耗时 41s） |
| **录入即搜到** | 无（索引从不更新） | 新建/修改/流转/删除后 5 秒内可搜到 |
| **同义词** | 无 | 6 组种子词，搜「卷宗」也能出「档案」的档；保存即生效 |
| **结果缓存** | 无 | 30 秒缓存，命中后 <10ms；条目变更自动失效 |
| **分面** | 有但全宗显示 UUID | 显示全宗名称 |
| **单次检索** | 首次 200ms+ | 冷 100~200ms、热 0~10ms |
| **并发** | 未测 | 50 并发 P95 196ms、271 qps、0 失败 |

## 九、技术附录（给运维/开发，测试时可跳过）

**索引状态自检**

```bash
# ES 里的文档数应等于库里的有效条目数（当前 3469）
curl -s "http://127.0.0.1:9200/archive_items/_count"

# 集群健康应为 green（副本已归零，单节点不再 yellow）
curl -s "http://127.0.0.1:9200/_cluster/health?pretty"
```

**手工重建索引**

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Tianji@2024"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['accessToken'])")

curl -X POST http://127.0.0.1:3000/api/search/reindex -H "Authorization: Bearer $TOKEN"
# 预期：{"code":0,"data":{"indexed":3469}}，耗时约 40 秒
```

**自动兜底机制**（不需要人工干预）

- 条目写入后进 300ms 攒批队列 → 一次 bulk 写入 ES，成功后递增缓存版本号
- 每 5 分钟扫描「最近 20 分钟变更过」的条目重投索引，修复漏同步
- ES 拒绝大批量时自动二分重投，不会中断重建
