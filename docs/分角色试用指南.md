## 一、R0 系统管理员（admin）

**能看到**：全部 14 个菜单。核心试用：系统管理四件套 + 备份。

### 1.1 用户与角色（左侧「系统管理 → 用户与角色」）
- 列表页：看 5 个账号、状态、角色标签；顶部搜索框可按用户名过滤
- 右上角「**新建用户**」按钮 → 填用户名/密码(≥8位)/姓名/密级上限/勾选角色/数据范围 → 保存
- 行内操作：「**编辑**」（改密级、角色）、「**重置密码**」、「**禁用**」（禁用后该账号立即无法登录 —— 可拿 reader1 试：禁用 → 另开浏览器用 reader1 登录 → 被拒）
- 「**角色权限矩阵**」入口（同页）：查看/勾选 R0-R4 在各业务域的 READ/WRITE/DELETE 权限

### 1.2 操作日志（「系统管理 → 操作日志」）
- 全系统审计流水；**预览/下载原文、借阅审批、权限变更**是强制留痕，谁动过什么都能查到
- 顶部按对象类型（USER/ITEM/FILE/BORROW…）、操作（CREATE/UPDATE/PERM_CHANGE）、时间过滤
- 试用技巧：先用别的账号做几个操作，再回来看这里出现的新记录

### 1.3 数据字典（「系统管理 → 数据字典」）
- 保管期限 / 借阅事由 / 销毁原因 / 主题词等枚举的维护
- 试试「新增一个主题词」（如「批量导入」），然后到著录页的关键词下拉里看它出现

### 1.4 系统参数（「系统管理 → 系统参数」）
- 会话超时、借阅默认天数、水印文案、下载开关等 11+ 个参数
- 试用技巧：把「预览水印文案」改成自己名字 → 再以 reader1 预览任意 PDF → 水印变了

### 1.5 检索同义词（「系统管理 → 检索同义词」）
- 6 组种子词（如「档案 / 卷宗 / 案卷」）；新建组、启用/停用、删除
- 试用技巧：用 reader1 搜「卷宗」（库里没有这个词）→ 结果区会显示「已按同义词扩展召回：档案 案卷」

### 1.6 向量库与模型（「检索利用 → 档案知识库」顶部状态条）
- 看 `pgvector` / 嵌入模型 / 生成模型 / 已建向量条数
- 点「重建索引」可全量重建（3468 件约 15–20 分钟，期间检索可用）
- 详细维护说明见《用户使用手册》§6.7

### 1.7 备份恢复（「统计与运维 → 备份恢复」）
- 「**立即备份**」→ 生成备份记录；列表可下载/恢复（恢复前会二次确认）

## 二、R1 档案管理员（archivist1）—— 档案业务主力

**能看到**：工作台、检索利用、档案业务、统计报表（无用户管理/参数等系统管理菜单）。

### 2.1 全宗管理（「档案业务 → 全宗管理」）
- 看到两个全宗：文书档案全宗（WS）、模拟书籍档案全宗（DEMO-BOOK）
- 右上「**新建全宗**」：填全宗号（唯一）/名称/年度范围 → 建一个自己的测试全宗
- 全宗行点击 → 看年度/卷数统计

### 2.2 档案著录（「档案业务 → 档案著录」）—— 核心流程
1. 卷列表：顶部按全宗/年度/密级过滤；看到批量导入的几十个卷
2. 点「**新建卷**」：填标题/责任者/年度/保管期限/密级 → 保存（卷号由档号规则自动分配，如 `DEMO-BOOK-2026-PERM-0007`）
3. 点卷名进「**件列表**」→「**新建条目**」：填题名/责任者/文件编号/成文日期 → 保存（件号自动分配）
4. 条目详情 →「**上传文件**」：选一个本地 PDF/EPUB → 上传 → 状态变「已上传」→ 稍后变「抽取完成」（右下角或列表刷新可见）
5. 件操作：「**提交归档**」（草稿 → 待归档确认）；批量勾选后「**批量提交**」
6. 「**归档确认**」：对「待归档确认」的件点确认 → 状态「已归档」（这是 R1 的特权操作）
7. 卷内所有件归档后，卷列表行点「**卷归档**」→ 卷状态「已归档」
8. 试「**作废重编**」：挑一件已归档件 →「作废」→ 填原因 → 件进回收站，档号让位（档号唯一可变通道，强制留痕）

### 2.3 档号规则（「档案业务 → 档号规则」）
- 看 DEMO-BOOK 的规则 `[全宗号]-[年度(4)]-[保管期限]-[卷号(4)]-[件号(4)]`
- 「**新建规则**」可按全宗/分类定制；「**预览**」输入上下文直接看生成的档号样式

### 2.4 综合检索（「检索利用 → 综合检索」）
- 关键词搜「論語」「论语」「Confucius」→ 出结果后点条目 → 预览原文
- 高级过滤：密级 / 保管期限 / 年度 / 全宗
- **密级过滤实测**：检索页如无特殊过滤，王档（SECRET）能看到秘密件；此账号能预览全部三个密级

### 2.5 回收站（「档案业务 → 回收站」）
- 被作废/删除的件在此；「**恢复**」或「彻底删除」（保留期内可逆）

### 2.6 档案鉴定（「档案业务 → 档案鉴定」）—— P3 新增，R1 主场
1. 「**新建鉴定任务**」：名称 + 年度区间 + 可选的保管期限过滤；「仅鉴定已到期的档案」默认勾选（永久件不参评）
2. 点「创建并生成明细」→ 任务号 `JD2026-xxx`，总数约 3468 件（取消勾选时）
3. 点「**明细**」→ 勾选若干件 → 「继续保管 / 延期保管 / 移交 / **销毁**」
   - 延期必须选新保管期限；**销毁必须填鉴定意见**
4. 点「**执行**」→ 提示「保管 N / 延期 N / 移交 N / 销毁 0 / **待审批 N**」
   - 销毁没批之前不会被删，这是设计
5. 点「**提交销毁审批**」→ 任务行出现「销毁审批中」
6. 本人到「审批中心」做**初审同意** → 再让 approver1 做**领导批准** → 通过后销毁件自动进回收站

> 试「假完成」防护：新建一个只圈到少量件的小任务，全给结论并执行 → 任务变「已完成」；
> 若有任何一件仍是「未鉴定」，任务会一直停在「鉴定中」。

### 2.7 开放管理（「档案业务 → 开放管理」）—— P3 新增
1. 「**新建开放批次**」：名称 + 年度区间 + 纳入密级（选「秘密」只有 71 件，跑得快）
2. 点「**明细**」→ 勾选 → 四态结论：**条目开放 / 原文开放 / 不开放 / 再审查**（不开放与再审查建议填理由）
3. 点「**提交审批**」→ 未审的件自动收口为「不开放」（fail-closed），不要觉得是 bug
4. 到「审批中心」点同意 → 批次变「已开放」，开放标识自动写入档案表
5. 页面下方「**再审查队列**」看标了「再审查」的件

### 2.8 审批中心（「检索利用 → 审批中心」）
- 三个页签：**我的待办 / 审批实例 / 流程配置**
- 待办按**岗位**派单：同角色任一人可处理；「档案管理员初审」只有 R1 看得到，「领导批准」要到 R4 才出现
- 点「同意」推进；点「驳回」必须填意见（流程终止，单据回发起人）
- 「流程配置」里能看到内置两条流程 `WF-OPEN-BATCH`、`WF-APPRAISAL-DESTROY` 的环节流向

## 三、R2 部门兼职档案员（deptclerk1）—— 只管一个全宗的录入员

**能看到**：工作台、档案著录（仅 DEMO-BOOK 全宗）、检索（受限）、借阅。

**设计好的差异点（对比 R1 试）**：
1. 全宗管理页：**看不到 WS 全宗**（数据范围只授了 DEMO-BOOK）—— 这是「数据范围授权」的实测
2. 档案著录：可以建卷/建件/上传/提交，但**没有「归档确认」按钮**（归档确认是 ARCHIVE_CONFIRM 权限，R2 无）
3. 密级上限「内部」：**搜索和列表里看不到秘密件**；拿同一关键词分别用 R1/R2 搜，对比结果数
4. 试用路径：新建卷 → 新建条目 → 上传文件 → 提交归档 → 然后切回 archivist1 去做「归档确认」—— 这就是 R2→R1 的协作流

## 四、R3 借阅用户（reader1）—— 利用者视角

**能看到**：工作台、综合检索、片段检索、借阅管理（自己的申请）。只读业务数据。

### 4.1 综合检索 + 预览
1. 搜任意词 → 点条目 →「**在线预览**」：PDF/EPUB 内嵌阅读器，页面上有**水印**（管理员改过文案的话会显示新文案）
2. 控制使用（CONTROLLED）的件：预览受限或提示需借阅
3. 密级上限「内部」：结果里没有秘密件

### 4.2 借阅全流程（「检索利用 → 借阅管理」）—— 重头戏
1. 在检索结果或条目详情点「**申请借阅**」→ 选借阅事由（字典）+ 填说明 + 天数 → 提交
2. 借阅管理页：看自己的申请单，状态「待审批」
3. （切 approver1 审批，见下节）→ 通过后回来「**在线阅读**」/「**下载**」（下载受系统参数 `download.enabled` 控制，管理员可关）
4. 到期前「**续借**」；管理员可设逾期参数

### 4.3 片段检索（「检索利用 → 片段检索」）
- 全文级检索：输入书中词句（抽取完成的件才有全文），命中处显示**片段高亮**
- 抽取是异步的：搜不到全文时不是 bug，是该件还没轮到抽取（可用统计报表看抽取进度）

### 4.4 档案知识库 · 智能问答（「检索利用 → 档案知识库」）—— P4 新增
1. 顶部状态条确认「pgvector / 嵌入 / 生成」三个徽标都在
2. 提问 `劉克莊《一剪梅》中「束縕宵行十里強」的下一句是什麼？` → 点「**提问**」→ 等 3~10 秒
3. 看回答：应给出「挑得詩囊，拒了衣囊」并标 `[1][2]`；下方片段前两条是同一首词的两个版本（一件秘密、一件公开），点片段能跳原档
4. **密级隔离实测（最有说服力）**：退出换 `reader1`（内部级）问**同一个问题** → 它只会引用公开那件，秘密那件完全消失
5. 页面中部「主题词」点一个词直接提问
6. 反向验证：问「电子文件四性检测包括哪些内容？」→ 回答应明确说「未提及」（演示库没有这类档案），**不会编**

> 若模型不可用，页面会提示「嵌入模型不可用：问答会降级为全文词法召回 + 抽取式摘要」，功能不中断（不会报错页）。

## 五、R4 领导/查档审批人（approver1）

**能看到**：工作台（审批待办）、借阅管理（审批视角）、综合检索（SECRET 全量）。

### 5.1 审批借阅
1. 登录后工作台「待我审批」卡片有数字（reader1 提过申请的话）
2. 借阅管理 → 待审批单 → 看申请事由/条目密级 →「**通过**」或「**驳回**」（填意见）
3. 审批动作强制写审计日志（admin 在操作日志里能看到）

### 5.2 查档
- 密级上限「秘密」：三个密级都能搜到、能预览 —— 对比 R3 的结果差异
- 统计报表（如有权限）：看全宗卷件统计、借阅热度

### 5.3 销毁终审 / 开放批次审批（「检索利用 → 审批中心」）—— P3 新增
- 本账号对鉴定/开放**只有审批权、没有建档权**：菜单里看不到「档案鉴定」「开放管理」
- 「我的待办」里会出现两种单：**鉴定销毁审批（领导批准）**、**开放批次审批**
- 点开看单据摘要（任务号/批次数/件数）→ 「同意」或「驳回（必填意见）」
- 通过后业务自动执行：销毁件进回收站 / 开放标识写入档案表 —— 不需要再点第二次

> 注意：R1 初审那一环不会出现在 R4 的待办里（节点角色是 R1）。R1 同意后才轮到你。

## 六、推荐的一条完整试用动线（30 分钟）

1. **admin** 登录 → 系统参数改水印文案 → 退出

3. **archivist1** 登录 → 档案著录 → 找到那件 → **归档确认** → 顺手把卷归档 → 退出
4. **reader1** 登录 → 综合检索「論語」→ 预览（看水印）→ 申请借阅一件「控制使用」的件 → 退出
5. **approver1** 登录 → 工作台待办 → **审批通过** → 退出
6. **reader1** 再登 → 借阅管理 → 在线阅读已批件
7. **admin** 登录 → 操作日志：把第 2-6 步的所有痕迹翻一遍 → 统计报表看数字变化 → 备份恢复做一次备份

**P3/P4 追加动线（约 15 分钟，可与上面连做）**

8. **archivist1** 登录 → 档案鉴定 → 新建任务（取消「仅鉴定到期」，年度 1900–2026）→ 勾几件给结论（1 件延期到「永久」、1 件销毁填意见）→ 执行 → 看到「待审批 1」
9. 同一账号 → 提交销毁审批 → 审批中心 → 我的待办 → **初审同意**
10. **approver1** 登录 → 审批中心 → 我的待办 → **领导批准** → 通过
11. **archivist1** 回档案鉴定 → 任务行显示「销毁已批」→ 去回收站看那件（可还原）
12. **archivist1** → 开放管理 → 新建批次（纳入密级选「秘密」，约 71 件）→ 明细里给 3 件不同结论 → 提交审批 → 审批中心同意 → 批次变「已开放」

14. **archivist1** 登录 → 问同一个问题 → 引用前两条变成「秘密 + 公开」两件（这就是权限内联在召回里的效果，不是缓存差异）

## 七、已知边界（试用时遇到这些不是 bug）

> **2026-11-13 权限改造后**：侧栏菜单已按角色自动裁剪（「菜单即权限」）——reader1 只能看到
> 工作台/综合检索/借阅管理/片段检索；admin 看不到档案著录（R0 不接触档案内容，设计使然）。
> 检索结果的件详情/在线预览对借阅用户开放（密级与数据范围内），详情页新增「申请借阅」按钮。

| 现象 | 原因 |
|---|---|
| 某件全文搜不到 | 抽取队列还在消化（并发 4，约 3500 件需数小时）；统计报表可看进度 |
| reader1 搜不到某件 | 密级超过其上限（INTERNAL）或该件「控制使用」 |
| reader1 点开详情被拒「密级或数据范围不足」 | 行级校验正常拦截——这是安全功能不是故障 |
| EPUB 预览 | 内置图书阅读器（epub.js），可翻页/调字号/看进度 |
| TXT / MD / CSV / 代码文件预览 | 书籍排版阅读视图（衬线字体、字号可调） |
| MOBI/AZW3 预览 | 降级显示抽取正文（服务端解码出文本后展示） |
| deptclerk1 看不到 WS 全宗 | 数据范围只授了 DEMO-BOOK（故意的演示点） |
| deptclerk1 提交后状态停在「待归档确认」 | 归档确认是 R1 的动作（权限设计） |
| 批量导入的卷有少量重复名 | 首轮并发竞态产生的重复卷，可用 admin 作废清理 |
| `E:\免费书籍` 没录完的部分 | 18:00 截止未录完，重跑 `python import_to_archive.py` 断点续录 |
| 鉴定任务总数比 3468 少很多 | 「仅鉴定已到期的档案」默认勾选；永久件不参评，未到期的 10/30 年件被排除 |
| 开放批次提交后改不了结论 | 审批中明细锁定；要改只能撤回或作废重开 |
| 未审的件提交后全变「不开放」 | fail-closed 设计：宁可少开放，不可错开放 |
| 开放标识只在件详情页可见 | 详情页头部有「条目开放 / 原文开放」徽标；检索结果列表暂无该标记 |
| 销毁件在回收站还能看到、能还原 | 销毁是软删除；真删要回收站「彻底删除」 |
| 同一实例 R1 和 R4 都看不到待办 | 环节角色不匹配：初审属 R1、批准属 R4；同角色才可见 |
| 审批超时不会自动通过 | 刻意保守：超时只告警，避免销毁被自动放行 |
| 知识库回答偶有重复句 | 本地 8b 模型能力所限；换更大模型可改善，演示机吃不消 |
| 知识库显示「数组回退」 | pgvector 扩展不可用，检索降级走词法；不是故障，但建议让 admin 检查镜像 |
