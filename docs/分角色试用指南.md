## 一、R0 系统管理员（admin）

**能看到**：全部 14 个菜单。核心试用：系统管理四件套 + 备份。

### 1.1 用户与角色（左侧「系统管理 → 用户与角色」）
- 列表页：看 5 个账号、状态、角色标签；顶部搜索框可按用户名过滤
- 右上角「**新建用户**」按钮 → 填用户名/密码(≥8位)/姓名/密级上限/勾选角色/数据范围 → 保存
- 行内操作：「**编辑**」（改密级、角色）、「**重置密码**」、「**禁用**」（禁用后该账号立即无法登录 —— 可拿 reader1 试：禁用 → 另开浏览器用 reader1 登录 → 被拒）
- 「**角色权限矩阵**」入口（同页）：查看/勾选 R0-R4 在各业务域的 READ/WRITE/DELETE 权限

### 1.2 操作日志（「系统管理 → 操作日志」）
- 全系统审计流水；**预览/下载原文、借阅审批、权限变更**是强制留痕，谁动过什么都能查到
- 顶部按对象类型（USER/ITEM/FILE/BORROW…）、操作（CREATE/UPDATE/PERM_CHANGE）、时间过滤
- 试用技巧：先用别的账号做几个操作，再回来看这里出现的新记录

### 1.3 数据字典（「系统管理 → 数据字典」）
- 保管期限 / 借阅事由 / 销毁原因 / 主题词等枚举的维护
- 试试「新增一个主题词」（如「批量导入」），然后到著录页的关键词下拉里看它出现

### 1.4 系统参数（「系统管理 → 系统参数」）
- 会话超时、借阅默认天数、水印文案、下载开关等 11+ 个参数
- 试用技巧：把「预览水印文案」改成自己名字 → 再以 reader1 预览任意 PDF → 水印变了

### 1.5 备份恢复（「统计与运维 → 备份恢复」）
- 「**立即备份**」→ 生成备份记录；列表可下载/恢复（恢复前会二次确认）

## 二、R1 档案管理员（archivist1）—— 档案业务主力

**能看到**：工作台、检索利用、档案业务、统计报表（无用户管理/参数等系统管理菜单）。

### 2.1 全宗管理（「档案业务 → 全宗管理」）
- 看到两个全宗：文书档案全宗（WS）、模拟书籍档案全宗（DEMO-BOOK）
- 右上「**新建全宗**」：填全宗号（唯一）/名称/年度范围 → 建一个自己的测试全宗
- 全宗行点击 → 看年度/卷数统计

### 2.2 档案著录（「档案业务 → 档案著录」）—— 核心流程
1. 卷列表：顶部按全宗/年度/密级过滤；看到批量导入的几十个卷
2. 点「**新建卷**」：填标题/责任者/年度/保管期限/密级 → 保存（卷号由档号规则自动分配，如 `DEMO-BOOK-2026-PERM-0007`）
3. 点卷名进「**件列表**」→「**新建条目**」：填题名/责任者/文件编号/成文日期 → 保存（件号自动分配）
4. 条目详情 →「**上传文件**」：选一个本地 PDF/EPUB → 上传 → 状态变「已上传」→ 稍后变「抽取完成」（右下角或列表刷新可见）
5. 件操作：「**提交归档**」（草稿 → 待归档确认）；批量勾选后「**批量提交**」
6. 「**归档确认**」：对「待归档确认」的件点确认 → 状态「已归档」（这是 R1 的特权操作）
7. 卷内所有件归档后，卷列表行点「**卷归档**」→ 卷状态「已归档」
8. 试「**作废重编**」：挑一件已归档件 →「作废」→ 填原因 → 件进回收站，档号让位（档号唯一可变通道，强制留痕）

### 2.3 档号规则（「档案业务 → 档号规则」）
- 看 DEMO-BOOK 的规则 `[全宗号]-[年度(4)]-[保管期限]-[卷号(4)]-[件号(4)]`
- 「**新建规则**」可按全宗/分类定制；「**预览**」输入上下文直接看生成的档号样式

### 2.4 综合检索（「检索利用 → 综合检索」）
- 关键词搜「論語」「论语」「Confucius」→ 出结果后点条目 → 预览原文
- 高级过滤：密级 / 保管期限 / 年度 / 全宗
- **密级过滤实测**：检索页如无特殊过滤，王档（SECRET）能看到秘密件；此账号能预览全部三个密级

### 2.5 回收站（「档案业务 → 回收站」）
- 被作废/删除的件在此；「**恢复**」或「彻底删除」（保留期内可逆）

## 三、R2 部门兼职档案员（deptclerk1）—— 只管一个全宗的录入员

**能看到**：工作台、档案著录（仅 DEMO-BOOK 全宗）、检索（受限）、借阅。

**设计好的差异点（对比 R1 试）**：
1. 全宗管理页：**看不到 WS 全宗**（数据范围只授了 DEMO-BOOK）—— 这是「数据范围授权」的实测
2. 档案著录：可以建卷/建件/上传/提交，但**没有「归档确认」按钮**（归档确认是 ARCHIVE_CONFIRM 权限，R2 无）
3. 密级上限「内部」：**搜索和列表里看不到秘密件**；拿同一关键词分别用 R1/R2 搜，对比结果数
4. 试用路径：新建卷 → 新建条目 → 上传文件 → 提交归档 → 然后切回 archivist1 去做「归档确认」—— 这就是 R2→R1 的协作流

## 四、R3 借阅用户（reader1）—— 利用者视角

**能看到**：工作台、综合检索、片段检索、借阅管理（自己的申请）。只读业务数据。

### 4.1 综合检索 + 预览
1. 搜任意词 → 点条目 →「**在线预览**」：PDF/EPUB 内嵌阅读器，页面上有**水印**（管理员改过文案的话会显示新文案）
2. 控制使用（CONTROLLED）的件：预览受限或提示需借阅
3. 密级上限「内部」：结果里没有秘密件

### 4.2 借阅全流程（「检索利用 → 借阅管理」）—— 重头戏
1. 在检索结果或条目详情点「**申请借阅**」→ 选借阅事由（字典）+ 填说明 + 天数 → 提交
2. 借阅管理页：看自己的申请单，状态「待审批」
3. （切 approver1 审批，见下节）→ 通过后回来「**在线阅读**」/「**下载**」（下载受系统参数 `download.enabled` 控制，管理员可关）
4. 到期前「**续借**」；管理员可设逾期参数

### 4.3 片段检索（「检索利用 → 片段检索」）
- 全文级检索：输入书中词句（抽取完成的件才有全文），命中处显示**片段高亮**
- 抽取是异步的：搜不到全文时不是 bug，是该件还没轮到抽取（可用统计报表看抽取进度）

## 五、R4 领导/查档审批人（approver1）

**能看到**：工作台（审批待办）、借阅管理（审批视角）、综合检索（SECRET 全量）。

2. 借阅管理 → 待审批单 → 看申请事由/条目密级 →「**通过**」或「**驳回**」（填意见）
3. 审批动作强制写审计日志（admin 在操作日志里能看到）

### 5.2 查档
- 密级上限「秘密」：三个密级都能搜到、能预览 —— 对比 R3 的结果差异
- 统计报表（如有权限）：看全宗卷件统计、借阅热度

## 六、推荐的一条完整试用动线（30 分钟）

1. **admin** 登录 → 系统参数改水印文案 → 退出
2. **deptclerk1** 登录 → 全宗管理（只见 DEMO-BOOK）→ 档案著录：建卷 → 建件「我的测试件」→ 上传一个 PDF → 提交归档 → 退出
3. **archivist1** 登录 → 档案著录 → 找到那件 → **归档确认** → 顺手把卷归档 → 退出
4. **reader1** 登录 → 综合检索「論語」→ 预览（看水印）→ 申请借阅一件「控制使用」的件 → 退出
5. **approver1** 登录 → 工作台待办 → **审批通过** → 退出
6. **reader1** 再登 → 借阅管理 → 在线阅读已批件
7. **admin** 登录 → 操作日志：把第 2-6 步的所有痕迹翻一遍 → 统计报表看数字变化 → 备份恢复做一次备份

## 七、已知边界（试用时遇到这些不是 bug）

| 现象 | 原因 |
|---|---|
| 某件全文搜不到 | 抽取队列还在消化（并发 4，约 3500 件需数小时）；统计报表可看进度 |
| reader1 搜不到某件 | 密级超过其上限（INTERNAL）或该件「控制使用」 |
| deptclerk1 看不到 WS 全宗 | 数据范围只授了 DEMO-BOOK（故意的演示点） |
| deptclerk1 提交后状态停在「待归档确认」 | 归档确认是 R1 的动作（权限设计） |
| 批量导入的卷有少量重复名 | 首轮并发竞态产生的重复卷，可用 admin 作废清理 |
| `E:\免费书籍` 没录完的部分 | 18:00 截止未录完，重跑 `python import_to_archive.py` 断点续录 |
