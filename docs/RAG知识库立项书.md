## 1. 立项决定

**决定：立项，且本期不实施。**

**为什么"立"** —— 三件事已经具备，值得固化为正式项目而不是留在"待议"：

1. **需求判据已定且不会变**：F-22 的三条硬口径（引用可溯源 / 未命中明确提示"无依据" / 私有化无外网依赖）是档案系统的合规底线，不是可选项。这决定了技术选型的天花板，越早锁定越省返工。
2. **地基已存在，且是"两端实、中间空"**：契约、权限前置过滤、审计、表结构、ES 8.13.4+IK、前端页面都在；缺的是中间的 chunk 生产与向量化。这种结构最怕的不是"没有"，而是"以为有"。
3. **有两个真实缺陷必须挂账**：`D-2`（向量空间不一致）与 `D-3`（召回顺序错位）。它们当时因 501 未暴露，一旦被人"顺手打开开关"就会变成看起来能用、实际给出噪声排序的能力。**挂账比记在脑子里可靠。**（裁决后当日即按 G-4 修复，见 §4 与 `0bbf744`。）

**为什么"不做"** —— 三个前置条件一个都没满足：

1. **硬件没结论**。闭网内只能 CPU 推理，而现有 K10 门槛只有内存 `≥8GB（建议 16GB）`，无 CPU 核数、无 GPU、无指令集要求。B 档所需内存（≥16GB，建议 32GB）与现状差一档，**这是门槛变更，不是软件改动**。
2. **交付面没裁定**。模型权重 2~5GB，直接冲击刚达成的「一个安装包即完整安装」（当前整包 1,765,044,444 B）。这个裁定不能由工程单方面做。
3. **缺陷未修（已解除）**。A/B 两档都建立在"向量空间正确 + 召回顺序正确"之上。该条已于 2026-11-10 按 G-4 闭合（`0bbf744`），故当前"不做"的依据只剩前两条：**硬件无结论、交付面未裁定**。地基已正，但还没有地方可盖。

**一句话**：立项是为了**把判据、缺陷、前置条件钉在纸上**；不实施是因为**现在动手既缺硬件结论，又会盖在缺陷上**。

## 2. 项目目标（分档，逐档递增）

| 档位 | 目标 | 明确**不是**目标 |
| --- | --- | --- |
| **A 检索增强** | 用户能用自然语言检索到**原文片段**，返回档号+片段+密级，可点进条目；越权片段零返回 | 不生成任何自然语言答案；不做摘要 |
| **B RAG 问答** | 基于召回片段生成**带出处**的答案；片段为空时明确"无依据" | 不允许引入片段外知识；不允许无引用结论 |
| **C 导读页（LLM Wiki 受限形态）** | 按全宗/年度生成**带引用**的导读，页首标注"AI 生成、仅供导览、不作为凭证" | **不做**百科式改写；不做无引用的生成摘要 |

**C 档已裁定不做独立档位**（理由见可行性评估 §3：改写无法逐句溯源，直接违 F-22 判据与档案凭证价值）。仅保留"带引用导读"这一受限形态，且优先级低于 B。

## 3. 范围界定

### 3.1 在范围内

- chunk 切分与 `kb_entry` 写入（密级**必须**来自条目元数据，不得由 chunker 推断）
- 向量化提供方接入（本地模型，可配置切换）
- 检索后端改造：ES `dense_vector` + kNN，**权限条件下推为检索约束**
- `/api/kb/*` 从 501 转为真实能力（分档推进，逐档可回退）
- 前端 `KbPage` 从"未启用"转为能力页
- 配套测试、迁移脚本、文档（含中文版）

### 3.2 不在范围内（本期及可预见期内）

- 跨库/跨系统的知识图谱融合
- 多模态检索（图片/音视频内容理解）—— 与 F-22 无关，属新需求
- 模型训练、微调、蒸馏
- 联网检索、外部知识源接入（**闭网红线，永久不做**）
- 问答结果作为档案凭证使用（**永久禁止**）
- 移动端问答（F-24 未启动）

## 5. 验收口径

继承 F-22，不新增也不放宽：

| 判据 | 出处 | 验收方式 |
| --- | --- | --- |
| 答案引用可溯源到具体条目 | `产品需求文档.md:173` | 抽检：每条结论可点击到 `danghao` 对应条目与原文片段 |
| 未命中明确提示"无依据" | 同上 | 构造无匹配问题，必须返回明确"无依据"，**不得返回相似度低但看似相关的编造内容** |
| 按密级/全宗隔离 | 同上 | **越权返回 0 条**，且该判据不可为召回率让步 |
| 私有化、无外网依赖 | 同上 | 运行期网络隔离下全链路可用；证据含"零外呼"验证记录 |

**两条不可谈判的硬约束**（来自既有代码与合规口径，非本立项新设）：

1. **权限过滤只许改"时机"，不许改"严格度"**。`buildKbFilter` 是硬性验收要点 3（`系统架构设计.md:64,765`）。为召回率放宽过滤 = 直接否决。
2. **「不臆造」是代码级约束**。`KbPage.tsx` 已写明"绝不编造答案"。任何生成能力都必须先过这条，否则不上线。
